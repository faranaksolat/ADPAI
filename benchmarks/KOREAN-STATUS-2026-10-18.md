این گزارش مربوط به اجرای ساختگی و بررسی اولیهٔ همان روز است. وضعیت تازهٔ
عکس‌های واقعی در [گزارش گردآوری انبوه](BULK-STATUS-2026-10-18.md) آمده است؛
صفرِ زیر، شمار اجرای اولیه است و نباید به وضعیت فعلی گردآوری تعمیم داده شود.

**ابزار سنجش و اصلاحات اولیه آماده‌اند؛ دیتاست واقعی و اعتبارسنجی روی
بسته‌بندی واقعی هنوز انجام نشده‌اند. تعداد عکس واقعی: صفر. آموزش مدل:
انجام نشده.** این گزارش، وضعیت تازه‌تر از گزارش ۱۷ اکتبر است.

## نتیجهٔ بررسی‌های تکمیل‌شده

- `npm test`: هر **۶۹ تست JavaScript موفق**؛ صفر ناموفق یا skipped.
- `.venv/bin/python -m unittest discover -s tests -p 'test_*.py'`:
  هر **۱۲ تست Python موفق**.
- `npm run test:browser` و `npm run test:mobile-web`: موفق؛ این دو بررسی
  مسیر صفحه، رابط کاربری و PWA/بستهٔ موبایل را با OCR کنترل‌شده می‌سنجند.
- ابزار سنجش نهایی روی **۱۸ تصویر ساختگی از ۹ الگو**، با Tesseract واقعی
  و مدل‌های رسمی محلی `kor/eng/fra` اجرا و با exit code صفر کامل شد.
  همهٔ تصاویر development هستند؛ مجموعهٔ holdout یا ۱۸ محصول مستقل نداریم.
- فایل‌های منبع/مدل و manifest/تصاویر در پایان دوباره کنترل شدند.
  تغییر تصویر، خروج از پوشه با symlink، نشت خانوادهٔ محصول بین splitها و
  خروجی گمشده نمی‌توانند یک سنجش ظاهراً موفق بسازند.
- محدودیت مصرفی که اجرای نهایی روز قبل را متوقف کرده بود، در این نوبت
  مانع اجرا نشد. این نتیجه به معنی رفع محدودیت منبع عکس نیست.

## چرا دیتاست واقعی و آموزش تکمیل نشده‌اند

در بررسی تازه، endpoint جست‌وجوی `world.openfoodfacts.org` پاسخ HTTP 503
داد. `images.openfoodfacts.org` پاسخ HTTP 200 همراه با متن صریحِ توقف
درخواست‌های خودکار به دلیل بار زیاد سرویس برگرداند. بنابراین دانلود
متوقف شد. پاسخ ۲۰۰ با این متن، دانلود موفق عکس محسوب نمی‌شود.

چند مخزن GitHub مربوط به OCR/مواد اولیهٔ کره‌ای بررسی شدند؛ عکس‌های
دارای مجوز روشن و مناسب این ارزیابی در آن‌ها به دست نیامد. عمومی بودن
کد یا وجود عکس در یک مخزن، مجوز استفاده از دیتاست را ثابت نمی‌کند.
ابزار `collect-off.py` آماده است، ولی ارتباط واقعی موفق و گردآوری عکس
با آن هنوز تأیید نشده است؛ تست‌های آن از نمونهٔ API ساختگی استفاده می‌کنند.

بدون دادهٔ واقعی و متن مرجع مستقل، نمی‌توان گفت مدل به آموزش نیاز ندارد
یا آموزش آن دقت واقعی را بهتر کرده است. وزن مدل‌ها تغییر نکرده‌اند.
جزئیات خطاهای کره‌ای اصلاح‌شده در گزارش ۱۷ اکتبر ثبت شده‌اند؛ این‌ها
اصلاح قواعد/مسیریابی و حفظ اطمینان کلمه هستند، نه آموزش مدل.

## ادامهٔ لازم

۱. پس از رفع مشکل سرویس، یا از عکس‌های اصلیِ ارائه‌شده با حق استفاده،
یک پایلوت ۲۰–۴۰ محصول مستقل بسازیم؛ تصویر کامل و نمای نزدیک مواد/هشدارها
لازم است. متن و زمینهٔ آلرژن پیش از اجرای OCR بازبینی شوند. فیلدهای API
مرجع تأییدشده نیستند.

۲. خانواده‌های محصول و مجموعهٔ ارزیابی جدا را پیش از تنظیم مدل ثابت
کنیم. پایلوت تک‌بازبینی با برچسب provisional گزارش شود؛ مرجع انتشار به
دو بازبین مستقل و حل اختلاف نیاز دارد.

۳. خطاهای متن مرجع و خطاهای OCR جدا سنجیده شوند. اگر خطای واقعیِ خواندن
باقی ماند، ابتدا مدل/پیش‌پردازش را روی development مقایسه کنیم؛ آموزش
به دادهٔ آموزشی کافی و مجموعهٔ دست‌نخوردهٔ ارزیابی نیاز دارد.

۴. استخراج مواد، مثبت کاذب نارگیل، بازیابی هشدارها، timeout مدل‌های اضافی
و سرعت گوشی پیش از انتشار اپ ارزیابی شوند. نتایج نامطمئن همچنان
`unverified` هستند؛ هیچ خروجی خودکار «ایمن» فعال نشده است.

این تغییرات برای بررسی در شاخهٔ جدا آماده می‌شوند. سایت اصلی، APK نصب‌شده
و فروشگاه‌ها با این کار به‌روزرسانی نشده‌اند. روش اجرای مجدد در
[KOREAN-DATASET.md](KOREAN-DATASET.md) آمده است.
