# بهبود خواندن برچسب آرایشی — ۱٫۱۱٫۱

در نسخهٔ آزمایشی جدید، نام‌های بیشتری بازیابی می‌شوند؛ **آمادگی انتشار عمومی و دقت روی محصولات واقعی هنوز تأیید نشده است**. رفتار «نتیجهٔ نامطمئن، ایمن نیست» حفظ شده و فهرست دوزبانه همان ۳۳۲ مادهٔ اولیهٔ بازبینی‌نشدهٔ نسخهٔ قبل است. مدل عصبی آموزش مجدد ندیده است.

## تغییرات مشخص

- `src/cosmetic-items.js`: ترتیب واقعی کلمه‌ها در سطر OCR حفظ می‌شود. کد قبلی مرتب‌سازی هندسیِ منو را به فهرست مواد اعمال می‌کرد؛ ویرگول کوچکِ پایین سطر به سطر دیگری می‌رفت و دو اسم درست به هم می‌چسبیدند. حرف یا امتیاز کلمه جایگزین نمی‌شود.
- `src/ocr-worker.js`: واژه‌نامهٔ محلی به decoder داده می‌شود؛ پشتیبانی decoder کلاسیک فقط با گزینهٔ صریح فعال می‌شود. مسیر پیش‌فرض غذای بسته‌بندی و منو همچنان LSTM است. مقدار امتیازهای برگشتی دست‌کاری یا با چند خوانش جمع نمی‌شود.
- `src/cosmetic-ocr.js`: خواندن متنِ متراکمِ مواد آرایشی از استخراج منوی رستوران جدا شده است. دو شیوهٔ کره‌ای، سپس مدل انگلیسی اجرا می‌شوند. هر بار فقط یک worker فعال است؛ خطای یک مدل، نتیجهٔ معتبر مدل قبلی را پاک نمی‌کند. این‌ها یک خانوادهٔ OCR هستند و تأیید مستقل پزشکی محسوب نمی‌شوند.
- `src/cosmetics.js`: امتیاز یک token کلاسیکِ شامل چند ماده به تک‌تک مواد به‌عنوان اطمینان واژه‌ای نسبت داده نمی‌شود. متن بریده‌شده در حاشیهٔ crop و عنوان نامطمئن همچنان نیازمند بررسی‌اند. علامت کولون خوانده‌شدهٔ `ː` در عنوان پشتیبانی می‌شود؛ امتیاز کلی خط جایگزین امتیاز واژه نمی‌شود.
- مدل کامل کره‌ای `@tesseract.js-data/kor@1.0.0/4.0.0` در بستهٔ موبایل اضافه شده است: ۱۵٬۳۱۷٬۷۱۵ بایت خام، با SHA-256 برابر `9520bfe9e3cfc38d4a808e036b0287c88a1d37fb80b9a0a23928ddccdd20595b`. مدل کوچک غذا/منو جایگزین نشده است. cache جدا مانع بارگذاری اشتباهی مدل کوچک در decoder کلاسیک می‌شود. وب مدل عمومی را از مسیر نسخه‌دار jsDelivr می‌گیرد؛ عکس یا متن کاربر به آن ارسال نمی‌شود.
- زمان آماده‌سازی هر دور از بودجهٔ مشترک هر عکس کسر می‌شود؛ مهلت recognition و تعویض decoder نیز کنترل می‌شود؛ timeoutِ تعویض زبان/decoder نیز worker را متوقف می‌کند. پاسخ دیرهنگام نمی‌تواند خواندن تازه‌ای شروع یا نتیجهٔ معتبر قبلی را پاک کند.

## مقایسه با اجرای واقعی موتور

مرجع قبل: snapshot کد `98eb28f`، نه نسخهٔ فعال GitHub Pages. هر دو نسخه روی **همان ۱۰ کارت مصنوعی توسعه** اجرا شده‌اند: ۵ انگلیسی و ۵ کره‌ای، شامل مرطوب‌کننده، شوینده، مواد عطری و دو کارت با چهار عبارت عمداً خارج از فرهنگ. هش تصویر PNG هر جفت یکسان است. این کارت‌ها در توسعه استفاده شده‌اند؛ مجموعهٔ مستقل یا تصویر محصول واقعی نیستند.

| معیار در همین ۱۰ کارت | قبل | بعد |
| --- | ---: | ---: |
| نام قابل توضیح از ۵۶ نام مرجع | ۴۶ | ۵۰ |
| نام با خوانش و زمینهٔ فهرست معتبر | ۴۶ | ۴۸ |
| نام جاافتاده | ۱۰ | ۶ |
| نام اضافیِ شناخته‌شده | ۰ | ۰ |
| میانهٔ مشاهده‌شدهٔ پردازش دسکتاپ | ۸٫۱۰ ثانیه | ۵٫۷۷ ثانیه |

در کارت کره‌ای اولیه، بازیابی نام از ۳/۶ به ۶/۶ رسید؛ فقط ۵/۶ زمینهٔ معتبر فهرست دارند و نام نارگیل همچنان نیازمند بررسی نمایش داده می‌شود. کارت عطری کره‌ای نیز یک نام بیشتر برای توضیح دارد؛ زمینهٔ آن نام تأیید نشده است. این دو مورد در ستون زمینهٔ معتبر موفق شمرده نشده‌اند. «زمینهٔ معتبر» فقط یعنی عبور از قواعد فعلی OCR برای عنوان و متن فهرست؛ تأیید انسانی یا کامل‌بودن برچسب نیست.

شش نام کره‌ای هنوز جا می‌افتند: Sodium Hyaluronate، Disodium EDTA، Ethylhexylglycerin، Sodium Laureth Sulfate، Sodium Cocoyl Isethionate و Sodium Benzoate. «بازیابی برای توضیح» با تأیید حضور ماده در محصول یا مناسب‌بودن برای شخص یکی نیست. صفر نام اضافه در این کارت‌ها، precision واقعی بازار را ثابت نمی‌کند. cache اندازه‌گیری نشده و زمان دسکتاپ به گوشی تعمیم داده نمی‌شود.

**دروازهٔ شناخت کامل هنوز رد است**؛ شش نام جاافتاده و دو زمینهٔ نامطمئن باقی‌اند. نسخه در شاخهٔ آزمایشی می‌ماند. اسکنر روی سایت اصلی و APK نصب‌شده فعال نشده است؛ انتشار در فروشگاه‌ها هم انجام نشده است. آزمون عکس واقعی آرایشی و آزمون فیزیکی گوشی در این مقایسه صفر است.

## بازاجرا

```sh
npm run build:mobile
COSMETIC_EXTRA_CASES=1 node tests/real-cosmetic-ocr.mjs /tmp/cosmetics-current.json
```

اسکریپت با موتور واقعی و مدل‌های بسته‌بندی‌شده کار می‌کند؛ دسترسی HTTPS بیرونی در اجرا مسدود است. برای وضعیت فعلی، خروجی گزارش نوشته و سپس به‌علت رد دروازه exit code غیرصفر برگردانده می‌شود. گزارش‌ها نام‌های قابل توضیح و زمینهٔ معتبر را جدا می‌شمارند؛ خروجی نامطمئن موفقیت ایمنی محسوب نمی‌شود.

برای تکرار مقایسه، checkout جدا از `98eb28f` بسازید، همان dependencyهای قفل‌شده را نصب و بستهٔ آن را آماده کنید. اسکریپت همین نسخه را با `COSMETIC_APP_ROOT=/path/to/that-checkout COSMETIC_EXTRA_CASES=1` برای نسخهٔ قدیمی اجرا کنید. سپس:

```sh
node benchmarks/compare-cosmetics.mjs /tmp/cosmetics-before.json /tmp/cosmetics-current.json /tmp/cosmetics-comparison.json
```

مقایسه در صورت تغییر هش تصویر، کد evaluator، مرجع یا تعداد capture رد می‌شود. فایل‌های خام آزمایش‌های مدل در پوشهٔ نادیده‌گرفته‌شدهٔ `benchmarks/results/` هستند؛ مدل بزرگ‌تر به‌تنهایی مشکل را حل نکرد و هیچ غلط OCR به‌عنوان مترادف صحیح به فرهنگ اضافه نشد.

گام بعد: برطرف‌کردن خواندن شش نام باقی‌مانده با خوانشِ دقیق ناحیهٔ متن، سپس جمع‌آوری برچسب واقعی با مجوز و رونویسی مستقل. برنامهٔ داده و بازبینی تخصصی در [سند نسخهٔ اولیه](COSMETICS-1.11.0-fa.md) آمده است. بزرگ‌کردن فرهنگ یا نشان‌دادن یک هشدار کلی، جای ارزیابی واقعی و تفکیک حساسیت غذایی از پوستی را نمی‌گیرد.
