# مسیر آموزش و پاسخ آفلاین منو

این شاخه ابزار آماده‌سازی داده دارد؛ مدل آموزش ندیده و این ابزارها هنوز به سایت یا API متصل نشده‌اند.

## اجرای جمع‌آوری اولیه
از ریشه مخزن، در محیطی که Pillow نصب است:
```bash
python tools/collect_menu_seed.py --output benchmarks/data/menu-seed
python -m unittest discover -s tests -p 'test_*menu_seed.py'
python -m unittest discover -s tests -p 'test_offline_dish_lookup.py'
```
منبع: https://huggingface.co/datasets/HumynLabs/Korean_Menus_Image_Dataset
نسخه ثابت و مجوز اعلامی ناشر در manifest ثبت می‌شود. این دانلودر فقط ۱۸ فایل موجود در نسخه بررسی‌شده را دریافت می‌کند؛ خزنده Naver یا دیتاست بزرگ آموزش نیست. عکس‌ها برچسب OCR یا مواد اولیه تأییدشده ندارند. هش فقط تکرار بایتی را حذف می‌کند؛ تشخیص عکس مشابه و گروه‌بندی رستوران نیاز به مرحله جدا دارد.

## معماری هدف
عکس مشتری در ورک‌استیشن اصلاح جهت و اندازه می‌شود؛ OCR متن و مکان خطوط را استخراج می‌کند؛ نام غذا و قیمت با حفظ ارتباط مکانی جدا می‌شوند؛ نام غذا در پایگاه محلی جست‌وجو می‌شود. این مسیر هنگام درخواست مشتری نیاز به جست‌وجوی وب ندارد.
ابزار offline_dish_lookup.py اولین جزء مستقل این مسیر است: تطبیق دقیق نام و alias با نرمال‌سازی Unicode. ورودی آن نام یک غذاست، نه متن کل منو. تطبیق مبهم و ناشناخته نتیجه قطعی تولید نمی‌کند. پایگاه واقعی غذا هنوز باید تهیه و بازبینی شود.

ساختار پایگاه JSON: فهرست رکوردهای dish_id، aliases، typical_ingredients و sources. رکورد بدون منبع پذیرفته نمی‌شود؛ وجود منبع به‌تنهایی به معنی بازبینی صحت آن نیست. هیچ داده آزمایشی نباید به عنوان مواد واقعی غذا استفاده شود.
```bash
python tools/offline_dish_lookup.py --knowledge /path/to/reviewed-dishes.json --text 'نام غذا'
```

## سه نوع شواهد
- متن قابل مشاهده روی منو: متن، محدوده تصویر و منبع ثبت شود. خوانده‌شدن متن به معنی کامل‌بودن فهرست مواد نیست.
- مواد معمول دستور غذا: فقط احتمال؛ همراه منبع دستور و نسخه پایگاه.
- مواد اعلام‌شده رستوران: با هویت رستوران، غذا، تاریخ و منبع، جدا از دستور عمومی ذخیره شود.

از نام غذا نمی‌توان نبود حساسیت‌زا، گوشت خوک، الکل یا آلودگی متقاطع را تضمین کرد. نتیجه ناشناخته نباید به «فاقد ماده» تبدیل شود.

## آماده‌سازی آموزش
۱. برای هر تصویر متن کره‌ای دقیق، چندضلعی خطوط، نام غذا، قیمت مرتبط و متن ناخوانا برچسب‌گذاری شود.
۲. برچسب تولیدشده با OCR یا مدل، پیش‌نویس است؛ بازبینی انسانی جدا ثبت شود.
۳. عکس‌های تکراری و نزدیک، صفحات یک منو و یک رستوران در یک گروه بمانند. تقسیم train/validation/test بر اساس رستوران انجام شود.
۴. ابتدا OCR فعلی روی آزمون ثابت سنجیده شود: خطای کاراکتر، صحت نام غذا و قیمت، و خطای نسبت‌دادن مواد.
۵. سپس مدل ازپیش‌آموزش‌دیده با داده تأییدشده fine-tune شود؛ از ابتدا آموزش داده نشود.
۶. پذیرش نسخه جدید تنها پس از بهبود روی رستوران‌های خارج از آموزش و سنجش تأخیر روی ورک‌استیشن باشد.

هدف پیشنهادی اولین دور جمع‌آوری: ۵۰۰ تصویر متنوع از دست‌کم ۱۰۰ رستوران. این عدد هدف است، نه داده دریافت‌شده و نه تضمین کفایت آموزش. Naver منبع کشف رستوران است؛ URL، مالک عکس و وضعیت اجازه استفاده باید برای هر تصویر ثبت شود. دریافت فعلی از منبع عمومی بالا است.
