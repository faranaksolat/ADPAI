# آماده‌سازی ورک‌استیشن ADPAI — Ubuntu
وضعیت: بستهٔ آماده‌سازی؛ نصب، تست GPU و آزمون گوشی روی دستگاه واقعی هنوز انجام نشده است.

## معماری و مرز نسخهٔ اول
GitHub Pages فعلاً پردازش محلی خود را حفظ می‌کند. سرور خصوصی موجود pc_server.main با رابط اختصاصی خودش راه‌اندازی می‌شود. اتصال مستقیم Pages به API، CORS محدود به مبدأ سایت، مدیریت نشست کاربران و آدرس HTTPS ثابت، مرحلهٔ بعد هستند؛ صرف بالا آمدن این سرویس سایت را متصل نمی‌کند.
مسیرهای موجود: POST /api/jobs و GET /api/jobs/{id} با Bearer token. health فقط زنده بودن برنامه را نشان می‌دهد، نه آماده بودن OCR.
کد pc_server/recognition.py فعلاً device='cpu' دارد؛ requirements.txt نیز paddlepaddle CPU است. این بسته GPU را فعال نمی‌کند.

## هنگام رسیدن دستگاه
1. نصب Ubuntu Desktop 24.04 LTS از تصویر به‌روز رسمی؛ پیش از پاک‌کردن دیسک، نبودن دادهٔ لازم را تأیید کنید.
2. نصب درایور NVIDIA سازگار با Blackwell و open kernel modules از مسیر رسمی. نسخهٔ قدیمی درایور را کورکورانه نصب نکنید.
3. ثبت خروجی nvidia-smi، مقدار VRAM، نسخهٔ Ubuntu و فضای آزاد. مدل دقیق HP به‌تنهایی مقدار VRAM را ثابت نمی‌کند.
4. اتصال شبکه با کابل، تنظیم خاموش‌نشدن خودکار/Sleep، بررسی راه‌اندازی مجدد. سیستم‌عامل و درایور را پیش از راه‌اندازی سرویس آزمایش کنید.

## اجرای اولیهٔ محلی
پروژه Python 3.11.9 را ثبت کرده است؛ Python پیش‌فرض Ubuntu را جایگزین نکنید.
با یک Python 3.11 مستقل و قابل اعتماد، در ریشهٔ checkout:
```sh
python3.11 -m pc_server.launch --install --no-browser
```
این دستور .venv-pc می‌سازد، وابستگی‌های ثبت‌شده را نصب می‌کند و سرور را روی 127.0.0.1:8765 بالا می‌آورد. دانلود مدل‌ها نیازمند اینترنت است. لینک خصوصی چاپ‌شده را فقط روی همان دستگاه باز کنید؛ آن را منتشر نکنید.
اگر نصب wheel یا OCR شکست خورد، متن خطا و نسخه‌ها را ثبت کنید؛ نصب موفق را فرض نکنید.
ابتدا یک عکس منوی کره‌ای واقعی را از رابط companion پردازش کنید. سپس تست‌های موجود پروژه را طبق pc_server/README.md اجرا کنید.

## سرویس دائمی، پس از موفقیت اجرای دستی
فایل adpai-pc.service.example نمونه است و خودکار نصب یا فعال نمی‌شود.
در آن USERNAME و /ABSOLUTE/PATH/ADPAI را با کاربر عادی و مسیر واقعی checkout جایگزین کنید.
محیط Python همان .venv-pc باشد. از launcher برای systemd استفاده نکنید؛ launcher توکن و لینک خصوصی را چاپ می‌کند.
یک فایل /etc/adpai/pc.env با دسترسی محدود ریشه (پوشه 700، فایل 600) بسازید:
```text
ADPAI_PC_TOKEN=REPLACE_WITH_RANDOM_SECRET_AT_LEAST_32_CHARACTERS
PADDLE_PDX_MODEL_SOURCE=BOS
PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True
OMP_NUM_THREADS=2
```
مقدار نمونه را استفاده نکنید؛ یک توکن تصادفی محلی تولید و در فایل امن ذخیره کنید. توکن را در گیت، اسکرین‌شات یا این گفتگو قرار ندهید.
نمونهٔ سرویس تکمیل‌شده را به /etc/systemd/system/adpai-pc.service منتقل کنید؛ سپس:
```sh
sudo systemctl daemon-reload
sudo systemctl enable --now adpai-pc
sudo systemctl status adpai-pc
curl --fail http://127.0.0.1:8765/api/health
```
برای توقف و غیرفعال‌سازی:
```sh
sudo systemctl disable --now adpai-pc
```
رابط محلی با http://127.0.0.1:8765/#token=YOUR_PRIVATE_TOKEN جفت می‌شود. لینک خصوصی است. توکن عمومی مشترک برای کاربران سایت مناسب نیست.
تست ری‌استارت و OCR واقعی را دوباره انجام دهید. گزارش خطا را قبل از اشتراک‌گذاری از اطلاعات حساس پاک کنید.

## GPU: مرحلهٔ مستقل
پس از ثبت VRAM، جدول رسمی سازگاری PaddlePaddle GPU، CUDA و Blackwell بررسی شود. در محیط مجزا نصب و با یک inference واقعی و مشاهدهٔ GPU آزمایش شود.
صرف موفقیت nvidia-smi یا نصب CUDA به معنی استفادهٔ OCR از GPU نیست.
سپس تغییر انتخاب device به‌صورت تنظیم‌پذیر، تست CPU/GPU و مقایسهٔ خروجی روی تصاویر یکسان انجام شود. نصب CPU موجود را پیش از موفقیت محیط GPU حذف نکنید.
آموزش سنگین هم‌زمان با سرویس آزمایشی انجام نشود.

## دسترسی گوشی و اتصال سایت
برای تست خصوصی می‌توان پس از نصب رسمی cloudflared از launcher --share استفاده کرد؛ URL موقت ثابت نیست و عکس‌ها از زیرساخت Cloudflare عبور می‌کنند.
برای استفادهٔ دائمی: دامنه/زیر دامنه و تونل ثابت، احراز هویت، محدودیت درخواست و بارگذاری، و تست انقضای نشست آماده شود. پورت خام سرویس را روی اینترنت باز نکنید.
پیش از اتصال Pages، متن حریم خصوصی و رضایت ارسال تصویر اصلاح شود. کلید سرور نباید در JavaScript عمومی قرار گیرد.
ذخیرهٔ تصاویر برای آموزش، انتخابی و جدا از تحلیل باشد؛ پیش‌فرض عدم ذخیره. ظرفیت فعلی تک‌کار سنگین است، نه سرویس عمومی پرترافیک.

## داده و سنجش دقت
مجموعهٔ شروع پیشنهادی: 200–500 عکس واقعی دارای منشأ و مجوز ثبت‌شده، با تنوع فونت، ستون، نور و زاویه.
هر رکورد: image_id، restaurant_id، source، permission، sha256، متن دقیق، کادر/چندضلعی متن، dish_id، قیمت، ارتباط توضیح با غذا، وضعیت بازبینی انسانی.
مواد نانوشته را از نام غذا حدس نزنید. خروجی مدل، پیش‌برچسب است نه مرجع انسانی.
train/dev/test بر اساس رستوران و قالب منو جدا شوند؛ برش‌ها و نسخه‌های تغییرشکل‌یافته در همان split اصل بمانند.
معیارها: CER، بازیابی نام غذا، اتصال درست قیمت/شرح، خطاهای نسبت‌دهی مواد، زمان و مصرف VRAM. تست مستقل برای انتخاب مدل استفاده نشود.
دیتاست مناسب: https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=71553
شرایط دسترسی و مجوز آموزش/بازنشر قبل از دانلود بررسی شود؛ این بسته هیچ دیتاست واقعی دانلود یا مدل آموزش‌دیده‌ای ندارد.

## شرط پایان راه‌اندازی
- نصب وابستگی و OCR واقعی موفق؛ خروجی مرجع انسانی و خطاها ثبت شده.
- بدون توکن درخواست رد می‌شود؛ health به‌عنوان دقت مدل گزارش نمی‌شود.
- پس از reboot سرویس بالا می‌آید؛ یک عکس واقعی دوباره پردازش می‌شود.
- قطع اینترنت/سرور در رابط خطای روشن می‌دهد، نه نتیجهٔ «ایمن».
- اتصال HTTPS گوشی، احراز هویت و سیاست نگهداری داده آزمایش شده.
